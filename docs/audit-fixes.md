# Виправлення аудиту — жовтень 2026

## Порядок випуску

Перед розгортанням нового фронтенду застосуйте до спільного Supabase-проєкту міграції:

1. `sklad/supabase/036_atomic_inventory_audit.sql` — додає RPC `complete_inventory_audit`, ідентифікатор повтору та payload операції. Залишки й історія інвентаризації записуються однією транзакцією. Застарілі залишки відхиляються без часткових змін.
2. `sklad/supabase/037_atomic_attendance_day.sql` — оновлює один день/роль у поточному JSON табеля атомарним upsert, зберігаючи паралельні зміни інших днів/ролей.

Timestamp-дзеркала розміщено в `supabase/migrations/`. Старий фронтенд сумісний з новими міграціями, тому спершу слід оновити базу. Новий фронтенд без міграції 036 не завершить інвентаризацію; чернетка залишиться на пристрої. Не використовуйте стару послідовність клієнтських update як fallback.

Міграції перевіряються в `tests/atomic-migrations.test.mjs` на PostgreSQL через PGlite: конфлікт залишків, відкат після помилки під час update, повтор тієї самої операції, повтор ID з іншим payload, невалідна кількість і збереження сусідніх днів/ролей табеля. Це не підтвердження виконання міграцій на production.

## Поведінка застосунку

- Смiття: відповідь на попередній запис не очищає чергу новішої правки; підтвердження прив’язане до місяця, дня та payload.
- Інвентаризація: чернетка й request ID зберігаються в localStorage; навігація та reload її не скидають. При конфлікті потрібно оновити дані й повторно перерахувати відповідні товари. «Очистити» явно починає нову чернетку.
- Фото: цільовий товар фіксується до upload; відкриття іншого товару не змінює ціль асинхронного запису.
- Діалог дня: початковий фокус, замкнений Tab/Shift+Tab, inert-фон і повернення фокусу після Escape/закриття.
- Мобільний журнал: календар перед статистикою, швидка дія «Запис за сьогодні», компактний вибір місяця та згортуваний графік.
- Склад: окремі режими створення/поповнення; необов’язкові поля поповнення згортаються; мобільні Excel/оновлення доступні в меню.
- Картка запасів показує кількість позицій, що потребують поповнення (поріг 3, як у наявному розділі), а не суму метрів і штук.
- Помаранчевий текстовий token має достатній контраст у світлій темі; колір тексту на tertiary також узгоджено.
- Повідомлення при завантаженні каже «Дані оновлено», не «Збережено».

## Залежності та локальні іконки

Vite оновлено до 6.4.5, source-map-js — до виправленої версії. Замість xlsx використовується write-excel-file 4.1.1: експорт зберігає назви аркушів, ширини колонок, числа й українські рядки. Текст користувача не перетворюється на формули. Імпорт Excel не додавався.

Material Symbols Rounded постачається локально: `shared/material-symbols.css` і `shared/fonts/material-symbols-rounded.woff2`. Service worker v11 кешує обидва ресурси. Шрифт містить підмножину іконок з поточного коду; при додаванні нових іконок оновіть її:

```sh
python scripts/subset-material-icons.py /path/to/MaterialSymbolsRounded.woff2
```

Скрипт запускається з кореня репозиторію й потребує Python-пакетів `fonttools[woff]`. Це лише інструмент для оновлення шрифту; npm install/build не потребують Python. Оригінал: https://raw.githubusercontent.com/google/material-design-icons/master/variablefont/MaterialSymbolsRounded%5BFILL,GRAD,opsz,wght%5D.woff2

SHA-256 оригіналу, використаного для цієї версії: `3a0c75876e6e161f9afc145472130c25f5490c9434c0d5217d8745d155aa6183`. Ліцензія Apache 2.0 збережена в `shared/fonts/LICENSE`.

## Перевірки перед випуском

```sh
npm ci
npm test
npm run build
npm audit
```

Після застосування міграцій перевірте інвентаризацію на тестових даних: успіх, повтор при втраті відповіді, зміну залишку іншим клієнтом; для табеля — паралельне редагування різних днів. Браузерні перевірки цього виправлення виконувалися на локальних підставних даних, без production-записів.
